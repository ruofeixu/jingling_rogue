# B5d：水墨动效（A 档：预制、低成本）（2026-11-10）

> **上游：** [内测路线图](./2026-10-01-internal-beta-roadmap.md) B5。负责人看到「水墨渲染」展示后提出：界面交互和战斗也用水墨效果，和现在的游戏风格匹配。
> 观感真源：[../specs/2026-10-29-ink-design.md](../specs/2026-10-29-ink-design.md)。手感约束：[../specs/2026-08-21-feel-design.md](../specs/2026-08-21-feel-design.md) S1（闪白/位移全长 0.15–0.45 秒）。前一轮：[2026-11-01-B5c-style-unify.md](./2026-11-01-B5c-style-unify.md)。

**Goal：** 战斗和界面切换有「墨」的感觉，但不增加明显的 GPU 开销。目标机是低端安卓微信/抖音小游戏（负责人玩过复杂小游戏卡顿发热严重）。

## 为什么只做 A 档

推文里的效果是实时流体模拟（桌面浏览器）。小游戏上整屏流体 shader 每帧都要算，发热风险高。分三档：

| 档 | 内容 | 开销 | 决定 |
|---|---|---|---|
| A | 预制透明墨迹图 + 程序化缩放/淡出，只在事件时播一次 | 几乎为 0（平时不跑） | **本阶段做** |
| B | 低分辨率单 pass shader：点击处墨晕扩散 | 中，要实机测帧率 | A 完成、实机稳定后再决定 |
| C | 实时流体模拟 | 高 | 不进战斗；如要，只放标题/结算点缀并加画质开关 |

## 已有的东西（不重造）

- `MOTION`（fast 120 / normal 240 / 减少动效上限 150 ms）和 `motionDurationMs(base, reduceMotion)`。
- 战斗页：比例缓降的血条、掉血时立绘闪白（`BattleScreen.animateRatio`）、整页淡入。
- `reduceMotion` 已经从设置传到渲染层。

## 待确认（请负责人定）

1. 墨迹素材用哪种方式：
   - **a. 生图**：按项目的生图流程出 8–10 张透明墨迹（泼墨、溅墨、墨点、墨痕），统一入库到 `ui-art`。风格和现在的立绘最接近，需要一轮看图。
   - **b. 程序化**：用 Graphics 画不规则墨点，不要素材，质感偏弱。
   我建议 a。
2. 结算「胜 / 败」一笔挥墨写出来，是否要？（需要每个字一张透明图或逐笔遮罩，成本比其他项高）

## 方案

### Task 1：动效契约（core/presentation）
- [ ] 新增 `INK_FX`（比照 `HIT_FX`）：`splash`（受击溅墨）、`trail`（血条墨痕）、`wash`（转场洗墨）三组时长与尺寸。每项全长落在 0.15–0.45 秒；转场 0.24 秒以内。
- [ ] 「减少动效」下：不溅墨、不洗墨，只保留一次淡入，总时长 ≤ 150 ms。
- [ ] 测试钉死数字和上述上限。

### Task 2：素材
- [ ] 按第 1 个待确认项的结果出图，入库，逐张看图（确认图真的返回再描述）。
- [ ] 缩到 256 以内，全部进 `ui-art` 分包，不进主包；跟踪分包体积。

### Task 3：战斗里的墨
- [ ] 受击：在立绘上叠一张溅墨，缩放淡出（现有闪白保留）。
- [ ] 掉血：血条后面拖一道墨痕。
- [ ] 技能起手：按灵性选墨色（火 = 朱砂、水 = 淡墨），色必须来自调色板。
- [ ] 同一帧最多 3 个活动特效节点，用完销毁，不泄漏。

### Task 4：界面里的墨
- [ ] 页面切换：洗墨转场，切页不超过 0.24 秒。
- [ ] 按钮点击：点击位置一个小墨点扩散淡出，只在点击时创建。

### Task 5：验证
- [ ] `pnpm test`、`pnpm check:forbidden`、`pnpm check:pack`（主包 ≤ 4 MiB）、分包体积门。
- [ ] 无头浏览器截帧：受击的中间帧、转场中间帧，逐张看。
- [ ] 「减少动效」开关下的路径单独跑一遍。
- [ ] 实机帧率（微信/抖音开发者工具 + 真机）留给 B6，负责人先稍后测。

## 退出证据

截帧对比；所有时长在手感规格区间内；主包和分包体积门通过；负责人试玩确认。

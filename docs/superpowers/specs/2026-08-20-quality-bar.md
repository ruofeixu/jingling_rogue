# 质量与可玩验收条

> 禁止 Phaser、上游源码、官方名。核心不得 `import "cc"`。

本文件是 **F1–F12 系统对标完成之后** 的验收真源：交互易用、可玩、表现、平台质量。

系统覆盖仍以 [2026-08-17-full-feature-parity.md](./2026-08-17-full-feature-parity.md) 第 16 节为准（已全部勾完）。难度数字仍以 [2026-08-19-playability-bar.md](./2026-08-19-playability-bar.md) 为准。实施按 [../plans/2026-08-20-quality-roadmap.md](../plans/2026-08-20-quality-roadmap.md) 的 Q0→Q5，一次只做一个阶段。

**第 16 节勾完 ≠ 可玩已验收。** 机制在 core 里，不等于人能顺手打完、点了有反馈、立绘不是黑框。

## 1. 现状（2026-08-20）

已有、可复用：

- 无头 UI：`PreviewApp`、`walkPlayableUi`、`runUiSmoke`、`pnpm smoke`
- 几何：`layout.test.ts` 钉指挥格 / 模式钮 / 名牌 / 初始卡不重叠（竖屏+横屏）
- 上手：标题→模式→初始 ≤3 步；引导 10 波存活 ≥80%；死点击 <5%（`onboarding.test.ts`）
- 可玩：`pnpm sim:bench`；三档策略口径见 playability-bar
- 内容：经典 200 配表地板已由 `catalog.test.ts` 钉住（精怪 ≥120 等）
- 表现：第一批 9 张立绘 RGBA；收契时间线 `catch-fx`；物品为 Graphics 图标

缺口（本规格要关上的门）：

| 缺口 | 为什么现在会漏 |
|------|----------------|
| `sim:bench` 未进 `pnpm test` | PR 不挡低/中均波、高通关率 |
| 无头 UI ≠ Cocos 命中 | 立绘盖住 Button、z-order、Sprite rect 只在预览里炸 |
| 死点击只测引导路径 | 术签 / 囊 / 收契 / 换人 / 双人点目标未钉死 |
| 立绘 9 / 精怪 ≥120 | 其余仍是剪影 |
| 物品是矢量块 | 不是可读的真图标资产 |
| Funplay / 预览截图未产品化 | 黑框、溢出靠人眼 |
| 高策略 200 通关 | P2 小样本通关率 0%，200 种子门槛未当硬门 |
| wx/tt 真机 | 模板与主包检查有，真机预览未当阶段门 |

## 2. 质量分层（谁测什么）

三层缺一不可。声称某 Q 阶段完成时，必须写清测过哪一层。

### L1 无头逻辑（CI 必跑）

`pnpm test`、`pnpm check:forbidden`。改 core 再 `pnpm sync:core`。

覆盖：规则、配表地板、layout 几何、PreviewApp 点击、引导死点击、sim 观察面。

**测不到：** Cocos 节点树、Sprite 贴图、真实手指。

### L2 预览壳（改 `assets/scripts/` 必跑）

- 导出清单：`creator-entry.test.ts` 钉 Cocos 从 `jinglingCore` 引进的名字
- 命中：可点控件必须是 Button；装饰立绘/图标 `coverHit()`，不得盖住点击
- 贴图：远程 PNG `color type = 6`（RGBA）；`hasAlpha`；SpriteFrame.rect 对齐
- 主包：`pnpm check:pack` ≤4MB；立绘不进主包

能测则写成 Vitest / 脚本。人眼截图只作 L3 补充，不当唯一验收。

### L3 观感与真机（阶段清单，不挡 L1）

Creator 预览 `localhost:7456`、Funplay MCP（若已启用）、wx/tt 开发者工具。用来抓：黑框、裁切、动画是否「像收契」、真机点按延迟。清单见第 6 节，结果写入该阶段细计划的校准记录，不把用户当人肉截图机。

## 3. 交互易用（硬指标）

改 UI 的 PR 必须用测试或脚本证明，不能只写「感觉顺了」。

### 3.1 上手

- 标题 → 模式 → 初始 → 开战：**≤ 3 次确认**（已有 `START_PATH`）
- 引导策略（第一张术 + 残血喝药）**12 种子 × 10 波存活 ≥ 80%**
- 引导路径死点击 **< 5%**（点了 `waitingFor` / screen / log 都不变算死点击）

### 3.2 点了必有下文

对每个 `waitingFor`（出术 / 换人 / 点目标 / 收契 / 择境 / 坊市 / 奇遇）：

1. 场上至少有一个可见控件能推进状态
2. 点合法控件后：screen、`waitingFor`、log、HP、金钱 **至少一项变化**
3. 非法点（空地、已用尽的术）必须有一句 log，不得静默

无头扩 `walkPlayableUi` / `applySafeCommand`。Cocos 侧：控件可点面积 ≥ **44×44** 逻辑像素；装饰节点不得抢点击。

### 3.3 不迷路

- 战斗主指令：**术 / 队伍 / 囊 / 走** 四格互不重叠，且不与名牌、日志、顶栏重叠（layout 已钉一部分，改布局必须补测）
- **术签** 从「术」格可进可退；打开术签不得挡住「返回」
- 日志始终能读出「下一步该点什么」（复制用 `copy.ts`，禁止新造官方味名词）
- 败北 / 通关有 **再来一局**；任意子页有 **返回** 且不溢出面板

### 3.4 双方向

竖屏 750×1334、横屏 1334×750 各跑一遍第 3.2–3.3 的几何断言。新控件必须进 `screenLayout`，禁止在 `Boot.ts` 里写死坐标。

### 3.5 文案

- 大厅「名词」能解释当前 HUD 用词
- 禁用词扫描通过（`pnpm check:forbidden`）
- 玩家可见字符串不出现隐藏种族值、内部 id

## 4. 可玩性（硬指标）

数字口径不改，只把「建议跑」变成「过不了不能合」。

| 门 | 命令 | 何时 |
|----|------|------|
| PR | `pnpm sim:bench --tier all --seeds 40` | Q0 起并进 CI / `pnpm test` 的一环 |
| 夜间 | `--seeds 200` | Q2 起作为发布门槛，结果写入校准记录 |

三档目标（与 playability-bar 相同）：

| 档 | 目标（≥200 种子；PR 用 40 种子看趋势，允许更宽的容差，细计划里写死数字） |
|----|------|
| 低 | 均波 15–25 |
| 中 | 均波 40–60 |
| 高 | 经典 200 通关率 40–60% |

达不到：**只改公开口径数值**（伤害、等级闸、双人率、战后回复、商店权重），不给策略开作弊视野，不改观察面。

额外不可玩判定（无头即可）：

- 软锁：某一 `waitingFor` 没有任何合法命令 → 测试失败
- 五模式都能开战（已有 walk；保持）
- 短征 20 波可打完；经典至少能打到低档均波带

P2 记录（n=8）：低 17.8 合格；中 67.8 偏高；高通关 0%。Q2 必须用 40 种子重测后再调。

## 5. 表现（阶段门，不是第 16 节系统项）

| 项 | 最低完成定义 |
|----|----------------|
| 立绘 | 第一批 9 张无黑底、战斗与选初始能贴上；其余精怪剪影可辨灵性色 |
| 收契 | 投出 → 晃 → 收/挣脱，时长与 `catch-fx` 单测一致；预览能播 |
| 物品 | 镇物 / 小药 / 契印 / 灵糖 在囊与坊市有可区分 glyph（已有 `item-icon`） |
| 音频 | 设置里的开关必须改变可观察状态（静音标记即可，不强制原声资源） |

后续批次立绘、真图标、受击反馈放 Q3，不阻塞 Q0–Q2。

## 6. 预览 / 真机清单（L3）

改了 `Boot.ts` / `paint.ts` / `portrait.ts` / `kit.ts` 时，阶段细计划勾选，**不要让用户代点**：

1. 大厅 → 短征 → 三只初始都能开战（点卡本身，不是点卡外面的字）
2. 战斗：术、术签进出、队伍、囊、走 各点一次有 log
3. 名牌文字不叠；指挥格不叠日志
4. 有立绘的精怪无黑矩形；无立绘为剪影+光晕
5. 收契能看出投出与结果
6. 竖屏 / 横屏各一次（模拟器改尺寸即可）

Funplay MCP：Creator 扩展启用后可截图；未启用则用已有预览 URL + 无头浏览器。L3 失败要能写成 L1/L2 回归测试，避免同一 bug 再靠眼睛抓。

## 7. 明确不做

- 不为了「更像某款官方 UI」改底栏或十八系名
- 不把 Funplay / 截图当作唯一 CI
- 不在 Q0 扩内容规模（无尽 240 精怪属 Q4）
- 不在质量阶段读上游源码或官方种族值表
- 不把用户当回归测试员

---

## 8. 阶段完成的定义

一个 Q 阶段完成 = 该阶段细计划全部勾完 **且**：

1. `pnpm test`、`pnpm check:forbidden` 通过
2. 改了 core → `pnpm sync:core`
3. 改了 UI → 第 3 节相关断言仍绿
4. 改了难度 → 第 4 节对应种子门仍绿，并在细计划里留下校准表
5. 本规格对应章节的验收句，能在测试名字或脚本输出里找到，而不是只写在 PR 描述里

## 1. 结论

- 本机实际调用 Cocos Creator `3.8.2`：`/Applications/Cocos/Creator/3.8.2/CocosCreator.app/Contents/MacOS/CocosCreator`。
- 微信与抖音小游戏最终构建均由 Creator 完成，包含真实平台入口、引擎脚本和序列化资源，不是 `packages/platform/src/preview-pack.ts` 生成的占位包。
- 两个平台都未达到发布门：立绘仍被 Creator 合入主包；微信主包 `21,382,164 B`，抖音主包当前实测 `22,540,953 B`（构建时记录为 `22,540,951 B`，+2 B 来源见 5.1），均超过 `4,194,304 B`，且原始 `game.json` 声明了不存在的分包目录。
- 已使用微信开发者工具 Stable `2.02.2608060`（Electron `36.6.0`）与抖音开发者工具 `4.5.5` 导入真实输出。手工调整只发生在 `.u0-sim/`；但抖音工具在导入时自行改写了 `.u0-build/bytedance/bytedance-mini-game/project.config.json`（详见 5.1），该例外必须计入证据完整性。
- 抖音规范化副本可加载 Cocos 场景并打印初始选择流程日志，但模拟器画面是**白屏**，同时反复报告 `unknown spirit: [object Set]`；清空平台存储并刷新后仍是白屏，标题、初始选择与战斗三页都没有可用截图。
- 微信规范化副本可导入并打开模拟器，但在执行 `game.js` 前被 `project.config.json: libVersion field needs to be string, string` 阻断；内置 automator 因运行时未建立而超时，不能报告 Cocos 场景或性能数据。
- 已保存两个真实开发者工具窗口截图。它们证明当前白屏/阻塞状态，不是关键帧、`.shots` 或浏览器替代图；没有声称取得任何可用产品页面截图。
- 三张原创 SVG 关键帧通过 U0 K1 人工审查；它们仅表示后续引擎还原意图，不是 K2 实际 Cocos 截图。

因此 U0 已建立可复现的真实构建、平台导入和失败基线；包体、分包声明、微信配置兼容性和精怪数据恢复均仍是未解决缺陷。U0 不修复这些产品行为，也不进入 U1。

### 5.3 微信导入、规范化与编译阻塞

原始 Creator AppID `wx6ac3f5090a6b99c5` 被工具拒绝为不存在；`touristappid` 和空 AppID 也不能用于该 Mini Game 项目。用户提供有效 AppID `wxef87c1a7a5e18bbf` 后，创建隔离副本 `.u0-sim/wechatgame-wxef87c1a7a5e18bbf`：

1. 从 `game.json` 删除与抖音相同的不存在分包声明。
2. 仅在副本 `project.config.json` 中写入 AppID `wxef87c1a7a5e18bbf` 和项目名 `jingling-rogue-u0-sim`。
3. 原始输出的 `libVersion` 是字符串 `"game"`。微信 Stable `2.02.2608060` 报错：

```text
[project.config.json 文件内容错误]
project.config.json: libVersion field needs to be string, string
(env: macOS,mg,2.02.2608060; lib: 3.17.2)
```

在 `.u0-sim` 内依次尝试具体版本 `3.17.2`、删除公有/私有字段，以及按官方文档使用 `latest`，每次均关闭、重新导入并打开项目；错误仍在 `game.js` 执行前复现。

需要披露的副作用：微信开发者工具在打开该副本时**自行扩写了配置**，除上述三项外还向 `project.config.json.setting` 追加了 `es6`、`compileWorklet`、`uglifyFileName`、`uploadWithSourceMap`、`minifyWXSS`、`minifyWXML`、`babelSetting` 等字段，并新增顶层 `simulatorPluginLibVersion`、`packOptions`、`isGameTourist`、`editorSetting`，同时生成了原始构建中不存在的 `project.private.config.json`。这些均由 IDE 写入，不是手工修改，但确实使副本配置不再等同“原始 + 三处改动”。代码与资源目录仍与原始逐字节一致（见 5.1）。

微信 CLI `open` 与 `auto` 均成功，内置 `wechatide` 也成功导入并打开 fullMode 窗口；但由于小游戏运行时未建立：

- `simulator_screenshot` 返回 `waitForAutomatorReady timeout: timeout waiting for automator response`
- `automation_evaluate` 返回 `wx is not defined`
- 控制台缓冲读取为空

因此改用 macOS CoreGraphics 窗口 ID 仅捕获 `Wechat Devtools` 项目窗口，不包含整个桌面。证据：`docs/ui/baselines/evidence/2026-08-31/wechat-compile-config-error.png`

- `2636×1872` RGBA PNG，`660,970 B`
- 清晰显示微信开发者工具 Stable `2.02.2608060`、Mini Game 模拟器和相同 `libVersion` 编译错误

微信没有进入 Cocos 运行时，故不能报告首屏、标题、初始选择、战斗、Draw Call、FPS、内存或加载时间；将自动化超时或空控制台误写为性能数据是不成立的。

# B5b：界面与字体打磨（2026-11-01）

> **上游：** [内测路线图](./2026-10-01-internal-beta-roadmap.md) B5「视觉打磨」。负责人试玩反馈："交互界面和字体都非常差；调整窗口后很多到屏幕外了"。
> 观感真源：[../specs/2026-10-29-ink-design.md](../specs/2026-10-29-ink-design.md)。

**Goal：** 任何窗口尺寸下所有可点元素都在画面内、画面铺满窗口；文字层级清楚、可读；按钮不再出现"术（原因）"这种挤在一起的长文案。

## 证据（无头浏览器量测，脚本在 `/tmp/cdp/audit.mjs`、`/tmp/cdp/resize.mjs`，不入库）

对试玩包 `http://127.0.0.1:8099/` 在 5 种窗口尺寸 × 6 个页面量了每个文字和按钮的屏幕矩形，又在战斗页里连续改窗口尺寸：

| # | 问题 | 量测 |
|---|---|---|
| 1 | **改窗口尺寸后页面不重排** | 战斗页在 390×844 开局后改成 844×390：设计分辨率切到横屏 1334×750，但页面节点坐标不变（「术」按钮仍在 (-181,-495)），竖屏内容被缩成中间一小块（截图 `resize-resize_844x390.png`）。`AppShell.onResize` 只对诊断页和陈列页重挂。 |
| 2 | **画面不铺满窗口** | `ResolutionPolicy.EXACT_FIT` 只在宽高比恰好 750:1334 时铺满；390×844 上下各留约 70 px 灰边，背景图之外是空的。 |
| 3 | **字太小** | 正文 22、说明 16 设计像素；在 390 宽手机上缩放 0.52 后约 11 px 和 8 px。顶栏、名牌数字、按钮文字都偏小。 |
| 4 | **禁用按钮把原因塞进按钮** | 「队伍（没有可换的伙伴）」挤成一行，原因应该放到按钮下方或用灰态表达。 |
| 5 | 敌我立绘朝向相同 | 双方都朝右；敌方应水平翻转面向我方。 |

量测中**没有**元素的包围盒越出画布——但那是因为页面没重排，内容只是被缩小；负责人看到的"到屏幕外"出现在窗口比例和页面布局不一致时（例如先横后竖、或缩窄窗口后横竖判断翻转）。修好 #1、#2 后，再用同一脚本按"改尺寸后"量一遍。

## 方案

### Task 1：改尺寸后重排（#1）
- [x] RED：`app-shell-contract.test.ts` 断言 `onResize` 在方向或内容尺寸变化时对当前产品页调用 `route(this.routeId)`（保留弹层选中、未提交选择等壳层瞬时状态）。
- [x] 实现：`onResize` 比较新旧 viewport（方向与设计尺寸），变化时重挂当前页；节流到下一帧，避免拖动窗口时每帧重建。

### Task 2：铺满窗口（#2）
- [x] 设计分辨率按窗口比例取：竖屏宽固定 750、高 = 750 × 窗口高/宽（最低 1334，避免布局被压扁）；横屏高固定 750、宽按比例（最低 1334）。`ResolutionPolicy.SHOW_ALL` 换成按算好的分辨率 `EXACT_FIT`，等比不拉伸。
- [x] 现有布局函数本来就按 `frame.content` 的宽高算，长屏多出来的高度会自动分给留白。
- [x] RED：`viewport.test.ts` 断言 390×844 时设计高 = 1623、宽 750；375×667 时仍是 750×1334。

### Task 3：字号与层级（#3）
- [x] `TYPE` 调大：caption 16→20、body 22→28、title 28→40、display 44→72；`lineHeightRatio` 1.35 不变。
- [x] 同步检查控件高度：按钮高 ≥ 正文行高 ×1.6；名牌、顶栏按新字号算高度。`real-tokens.test.ts` 的 200% 文本门要继续过。
- [x] 标题字（书法）只用于 display 和页面大标题；数字（金、波次、HP）用系统字体加粗。

### Task 4：禁用原因不进按钮（#4）
- [x] 按钮上只写动作名，禁用时变灰；原因作为按钮下方一行小字（caption、淡墨）。
- [x] 文案契约测试（`u15-copy-hygiene.test.ts`）若锁了"（原因）"格式，同步改。

### Task 5：敌方立绘翻转（#5）
- [x] `BattleScreen` 敌方立绘节点 `scale.x = -1`。

### Task 6：验证
- [x] `pnpm test`、`pnpm check:forbidden`、`pnpm sync:presentation`；`assets/scripts/app/` strict 类型检查。
- [x] 重新构建试玩包；用审计脚本在 5 种尺寸 × 6 页 + 连续改尺寸量测：越界 0、灰边 0、正文在 390 宽手机上 ≥ 14 px。
- [x] 截图逐张看，发给负责人。

## 执行记录（2026-11-01）

量测前后对比（同一脚本，390×844 手机 / 1280×720 桌面）：

| 项 | 修改前 | 修改后 |
|---|---|---|
| 改窗口尺寸后重排 | 不重排，内容停在旧坐标 | 设计尺寸变化即重挂当前页；拖动不变比例时不重建 |
| 铺满窗口 | 手机上下灰边约 70 px；**横屏两侧灰边**（Canvas 仍是竖屏 750×1334，相机停在旧位置） | 5 种尺寸 × 6 页全部铺满 |
| 最小字号（390 宽手机） | 8 px | 12.5 px（正文 14.6 px） |
| 越界元素 | 0（但内容被缩成一块） | 0 |

做了的改动：
- `buildViewport`：设计分辨率按窗口比例取（短边 750，长边按比例且不小于 1334），配合 `EXACT_FIT` 铺满不拉伸。
- `AppShell.refreshViewport`：设完设计分辨率立刻 `Widget.updateAlignment()` + `Canvas._onResizeCamera()`。这是横屏灰边的真正原因：引擎的 Canvas Widget 不会在同一帧跟着新分辨率重排。`_onResizeCamera` 是引擎内部方法，升级 Cocos 时要回归。
- `AppShell.onResize`：设计尺寸变化时重挂当前页（原来只对诊断页重挂）。背景按实际设计尺寸铺。
- 字号：caption 16→24、body 22→28、title 28→40、display 44→76；按钮、名牌、顶栏、命令按钮高度同步加大。
- 按钮禁用原因不再写成"动作（原因）"挤在一行，改为动作名下面一行淡墨小字。
- 战斗立绘：新增 `PORTRAIT_FACES_LEFT`（按头部所在半边估出 8 张朝左），敌方朝左、我方朝右，双方面对面；名牌收窄，把横向空间让给立绘。
- 选宠页：灵性显示中文（原来是 `flame`）；详情四项排成两列两行，不再撑出面板。
- 版式测试新增 390×844、768×1024、1280×720 三种尺寸；`pnpm test` core 280 / presentation 400 / platform 17。

还没解决（截图可见）：
- 选宠页竖屏卡片又窄又高，立绘只占中间一小块。旧规格要求卡片 ≥ 屏高 30%，两者冲突，要负责人定取舍（例如卡片改成上下排列的大卡，或降低高度要求）。
- 横屏战斗页立绘偏小、右上大片空白：横屏左栏宽度有限。
- 320 宽极窄屏上说明文字约 10 px。

# B4：存档与平台适配（2026-10-31）

> **For agentic workers:** 按任务顺序执行，一次一个任务；每个任务先 RED 再实现。Steps 用 `- [x]` 跟踪。

**上游：** [内测准备路线图](./2026-10-01-internal-beta-roadmap.md) 的 B4「接微信/抖音 KvStore；本地模拟器先做存档往返、槽位列表、损坏恢复；真机最后统一验收」，以及内测总门第 7 条「本地模拟可保存/恢复至少一个槽；损坏存档安全回退，不丢账号进度」。

**Goal：** 发货入口（`boot.scene → Boot → AppShell → createProductDriver`）真的存档：局内自动写槽、账号随结算落库、存档页列出真实槽位并能读回、坏档不崩不丢账号。

## 现状（2026-10-31 探查）

- `RunController` 已有 `save(slot)` / `load(slot)` / `listSlots()`，走 core 的 `KvStore`（`save/local-store.ts`），但**发货链路从没调用过**：`createProductDriver()` 用 `new RunController()`，没注入 store。
- `AppShell` 的 `slots` 页读 `this.savedSlots`，只有 `setAccount()` 能写，发货链路也没人调。`slots.load.<n>` 能解析成命令，但 controller 不认。
- 存档页从标题进入，但"读档后去哪"没有路由。
- 账号只活在内存：`RunController.keptAccount`（B3 加的），关掉游戏就没了。开机也不读账号。
- `decodeRun` / `decodeAccount` 遇到坏 JSON 或版本不对**直接抛错**。`loadRunLocal` / `loadAccountLocal` 不接这个错。
- 读档后 `ClassicSlice.fromState` 把相位强制设为 `battle` 并重开当前波的战斗；不保存战斗中途、收契、奖励的中间态。
- 存储后端：Cocos 小游戏适配层把 `sys.localStorage` 映射到 `wx/tt.getStorageSync / setStorageSync`（引擎 `platforms/minigame/platforms/{wechat,bytedance}/wrapper/builtin/localStorage.js`）。旧 `Boot.kv()` 已用 `sys.localStorage` 包了一个 `KvStore`。所以**两平台都能直接用 `sys.localStorage`，不必走 `packages/platform` 的异步 `wx.getStorage`**。浏览器预览也是同一个接口。

## 决定

- **后端：`sys.localStorage` 包成 `KvStore`。** 理由见上：小游戏里已由引擎映射到同步存储 API，三端一致。`packages/platform` 的 `createPlatform` 暂不接（它的 `setStorage` 在回调前就 resolve，且不报失败）。云存档归 PvP 的 P5（要真登录），不在 B4。
- **存档粒度：** 每完成一波（回到 battle 相位开新波时）自动存当前槽；结算提交和回厅时存账号。读档从"该波开头"恢复，与 `fromState` 现有语义一致；战斗中途退出会重打这一波。这是有意的简化，写进存档页说明。
- **槽位：** 新局总写内部槽 0（界面显示"槽1 · 当前旅途"），开新局会覆盖它。槽 1–4（界面槽2–槽5）留给以后的手动存档，本阶段不写。存档页文案说明这条规则。
- **局结束：** 胜/负提交后清掉该槽（局已结束，不能再读回打一遍），账号单独保留。
- **坏档：** 解码失败的槽按"空槽"展示并标"存档损坏，已忽略"；坏账号回退为空账号前，先把原文另存到 `account.corrupt` 键，不覆盖丢失。

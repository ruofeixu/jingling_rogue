# U5：初始选择（2026-09-05）

**上游：** [路线图 U5](./2026-08-31-ui-productization-roadmap.md) · [产品规格](../specs/2026-08-31-ui-productization.md) · [关键帧](../../ui/keyframes/starter.svg)

**前置：** U1–U4 已完成。

## 目标

迁移 `starter` 一页：三卡比较、选中详情、费用/灵性、立绘 contain、确认与返回、资源 loading/error、横屏两栏。

## 非目标

- 不改初始精怪池、费用规则、契印规则、随机结果。
- 不迁移 `battle` 及其子页。
- 不新增或修改立绘资源。

## 失败测试（先 RED）

1. 候选顺序稳定：同一输入两次构造顺序一致。
2. 候选为空时确认按钮 `enabled:false` 且有原因；不允许出现两个一级确认。
3. 锁定候选带文字原因。
4. 立绘 `loading` 时确认不可用并说明原因；`error` 时给可重试动作且不重复开始旅途。
5. K1 关键帧标注的字段（费用、灵性、魂契、确认）必须都在 ScreenModel 里存在。
6. renderer 契约：不含玩法符号、颜色字面量；立绘尺寸走 `portraitFit`。

## 退出门

- `starter` 在 manifest 中为 `presentation`；五态与竖横屏可渲染，截图入档。
- 资源失败可重试且不重复开始旅途（同一确认 action 连点两次结果一致）。
- 逐页回退有效；U3/U4 页面无回归。
- 仓库全量验证通过；主包仍 ≤ 4 MiB。

### 实现要点与偏差

1. 新增 selector `selectStarter(account, seed)`：`unlockedStarters` 为空时回退到固定三只
   （`DEFAULT_STARTERS` = 灶狸/井蛛/桃梗），顺序稳定；费用走 `currentCost`，契印走
   `offerRelics` / `pickStartRelic`，不重算规则。
2. 立绘尺寸走 `portraitFit` 等比 contain；契约测试禁止本文件出现 `ellipse`，即"有图不画烘焙垫底"
   （与 A0 已验收的结论一致）。缺图时只画卡片与按钮，不伪造占位图形。
3. 立绘资源状态（ready/loading/error）由壳层的 `starterArt` 注入，属于瞬时 UI 状态；
   presentation 不读资源，也不因缺图改变玩法结果。
4. K1 关键帧标注的字段（费用、属性、契印、确认）都在 ScreenModel 的 `lines` 与 `primaryAction` 中，
   由 `starter.test.ts` 用正则断言，避免关键帧与模型漂移。
5. 真实立绘 SpriteFrame 由 `frames` 选项注入，当前壳层未预载（U6 起战斗页需要同一套预载逻辑，
   届时一并建立资源句柄层）。因此截图中卡片只有文字与按钮，这一点在证据里如实标注。

# 明亮童话志怪 UI 产品化路线图（U0–U11）

> **For agentic workers:** 每个阶段开工前必须另写该阶段详细 Implementation Plan；使用复选框逐步执行。一次只实施一个阶段，上一阶段退出门未通过时不得创建下一阶段工作变更。

**Goal:** 在保留 Cocos Creator 3.8.2 与 `packages/core` 的前提下，将 25 个产品面迁移到可测试的 presentation/AppShell，并通过竖横屏、五态、包体、性能与可访问性总门。

**Architecture:** `packages/core` 继续拥有玩法和状态；纯 TypeScript presentation 生成 ScreenModel；Cocos AppShell 负责页面宿主、方向、安全区、输入和生命周期。迁移期间按页面回退到旧 Boot 呈现，但任何时刻只有一个状态所有者。

**Tech Stack:** TypeScript / Vitest / Cocos Creator 3.8.2 / Python 3.11+ / pytest / Jujutsu

**真源：** [产品规格](../specs/2026-08-31-ui-productization.md) · [ADR-0001](../../adr/0001-ui-presentation-shell.md) · [参考矩阵](../../ui/reference-matrix.md)

## 全局纪律

- 固定顺序：`U0 → U1 → … → U11`。一次一阶段；不能并行预做页面、资源或重构。
- 开工前先读 clean-room、禁用词表、IP 圣经、本路线图和当前阶段细计划。
- 每份细计划必须写出准确文件路径、失败测试及预期失败、最小实现、验证命令、实际 Cocos Demo 和退出门；没有细计划不得改代码。
- 所有功能以失败测试开始。失败原因必须是待实现行为缺失，而不是语法、夹具或环境错误。
- 修改 core 后执行 `pnpm sync:core`；每阶段至少执行 `pnpm test`、`pnpm check:forbidden` 与该阶段专项检查。
- 实际截图和最终构建是证据真源。SVG、浏览器替身、`.shots` 和平台占位包不计通过。
- 下列细计划文件名是固定交付路径；未来创建文件不代表阶段已开工，只有用户明确开始该阶段才可实施。

## 阶段总览

| 阶段 | 范围 | 关键交付 |
|---|---|---|

| U1 | presentation/AppShell 骨架 | ScreenModel、路由清单、壳层与逐页回退开关 |
| U2 | 设计系统与五态组件 | token、排版、按钮、面板、状态页、方向/安全区容器 |
| U3 | 标题与模式 | `title`、`mode`，标题关键帧引擎还原 |
| U4 | 大厅资料页 | `settings`、契录、卵房、成就、统计、存档、名词页 |
| U5 | 初始选择 | `starter`，初始关键帧引擎还原 |
| U6 | 战斗主界面 | `battle`，战斗关键帧引擎还原与 HUD 数据流 |
| U7 | 战斗子界面 | `arts`、`switch`、`party`、`bag`、`target`、`catch` |

## U0：产品与架构基线

**详细计划：** `docs/superpowers/plans/2026-08-31-U0-ui-productization-baseline.md`。只按该计划执行；本路线图不替代其任务步骤。U0 不修改现有页面产品行为，也不进入 presentation。

**失败测试：** 页面审计在缺少任一 core screen、TOUR stop、`party` 或三关键帧时失败；构建审计在入口缺失、主包 `>4 MiB` 或检测到占位产物时失败。先看到模块/资产缺失导致的 RED，再创建最小审计实现与基线。

**Demo：** 展示页面/状态矩阵、三张 `750×1334` 原创关键帧；运行审计；打开两平台实际 Cocos 构建与带元数据截图。环境不可用时必须展示原始错误和复现步骤，不得替代证据。

**退出门：** 产品规格、路线图、ADR、参考矩阵无冲突；页面/TOUR/关键帧审计通过；实际构建审计能拒绝三类坏产物；主包与性能有真实基线；范围和禁用词检查通过。U0 完成前禁止 U1。

## U1：presentation 与 AppShell 骨架

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-01-U1-presentation-shell.md`，逐文件定义纯 TypeScript `ScreenModel`、screen manifest、AppShell 组合根、旧 Boot 页面回退适配器和测试夹具。

**失败测试：** 先证明同一 core 快照可生成确定 ScreenModel，未知 screen 被拒绝，壳层在竖/横 viewport 选择正确布局模式，且同一时刻不能同时挂载新旧 renderer；初始状态下测试因模块不存在而失败。

**Demo：** 实际 Cocos 启动 AppShell，显示诊断页并在竖横屏切换；通过 manifest 将一个无产品内容的审计路由在新宿主与旧呈现间回退，core 状态不重建。

**退出门：** 不迁移任何产品页；core 不导入引擎模块；AppShell 只管组合/生命周期；全局与逐页回退有效；无双状态源；专项测试和仓库测试通过。

## U2：设计系统与五态基础组件

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-02-U2-ui-foundations.md`，明确 token、排版、图标语义、按钮/面板/列表、loading/empty/error/locked、焦点、减少动效、SafeArea 与 ResponsiveFrame 的文件和 prefab 边界。

**失败测试：** 先用 token/布局测试钉死对比度、`44×44` 热区、`750×1334` 与 `1334×750` 安全区；状态组件缺少原因、主行动或可访问名称时失败；动画在减少动效下超过 `150 ms` 时失败。

**Demo：** 实际 Cocos 组件陈列页切换主题 token、五态、文本 200%、减少动效及竖横屏；现场展示长文、超长标签和安全区。

**退出门：** 基础组件无玩法判断；五态均可复用；自动对比度/热区/布局测试通过；组件陈列实际截图入档；尚未迁移产品页。

## U3：标题大厅与模式选择

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-03-U3-title-mode.md`，只迁移 `title`、`mode`，列出背景层、角色陪伴区、主次入口、模式卡、ScreenModel 映射和旧页回退。

**失败测试：** 先证明标题只有一个一级行动、模式锁定条件有文字、五态可注入、竖横屏无裁切，且 ScreenModel 事件只发命令不直接改 core；旧实现下断言失败。

**Demo：** 实际 Cocos 从冷启动进入标题，打开模式、查看锁定原因、返回；切换五态和方向；与标题关键帧并排说明意图差异。

**退出门：** `title`、`mode` 主任务完成；标题通过 K2；两页 normal/loading/empty/error/locked 与双向截图齐全；逐页回退有效；其他页面仍走旧呈现。

## U4：大厅资料与管理页

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-04-U4-lobby-pages.md`，依次覆盖 `settings`、`codex-list`、`codex-entry`、`eggs`、`achievements`、`stats`、`slots`、`glossary`，共享列表/详情壳但不混合各页业务适配器。

**失败测试：** 先为每页主行动及 empty/locked 语义写表驱动测试；追加长列表、无历史、未知条目、云端错误、重复重试和返回焦点恢复测试；未迁移页必须逐项失败而不是跳过。

**Demo：** 实际 Cocos 从标题遍历八类体验，展示空契录、锁定条目、无历史统计、空存档、错误重试、文本放大和横屏列表/详情双栏。

**退出门：** 所有大厅资料页可达并可返回；契录列表/详情分别有证据；空态不只是一张插图；存档操作幂等；U3 页面无回归；未覆盖页继续安全回退。

## U5：初始选择

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-05-U5-starter.md`，定义三卡比较、选中详情、灵性/费用、立绘 contain、确认/返回、资源 loading/error 与横屏两栏。

**失败测试：** 先证明候选顺序稳定、缺少候选不能确认、锁定原因可读、只能存在一个一级确认、立绘不变形且无烘焙垫底；K1 标注与 ScreenModel 字段不一致时失败。

**Demo：** 实际 Cocos 从模式进入初始选择，逐一比较灶狸、井蛛、桃梗，模拟资源慢载/失败/锁定并完成确认；展示竖横屏。

**退出门：** `starter` 五态与双向通过；初始关键帧通过 K2；资源失败可重试且不重复开始旅途；旧页可一键回退；玩法选择结果与迁移前一致。

## U6：战斗主界面

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-06-U6-battle-main.md`，只迁移 `battle`：战场、敌我名牌、战况文本、上方工具、右侧术法入口、动效事件和 ScreenModel 增量更新。

**失败测试：** 先钉死命令顺序、HP/灵力/状态展示、不可用命令原因、重复点击抑制、事件更新 p95 预算、减少动效及竖横屏布局；renderer 尝试计算伤害或改状态时失败。

**Demo：** 实际 Cocos 用固定种子完成数回合，展示受击、倒下、状态变化、命令锁定、loading/error 恢复、减少动效与横屏战斗。

**退出门：** `battle` 通过 K2；核心回合结果与迁移前快照一致；95% UI 采样 `≥50 FPS`、峰值 Draw Call `≤120`；战斗子界面仍可回退且能返回新战斗页。

## U7：战斗子界面

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-07-U7-battle-overlays.md`，逐个迁移 `arts`、`switch`、`party`、`bag`、`target`、`catch`，定义弹层栈、取消语义、目标合法性和焦点恢复。

**失败测试：** 先覆盖无可用术法、无可换目标、空囊、无合法目标、无镇物、非法目标与连续开关弹层；`party` 即使无 TOUR stop 也必须在覆盖审计中失败先行。

**Demo：** 实际 Cocos 从同一场战斗依次打开六个产品面，完成术法选目标、换位、用物与放过；每个弹层展示返回、empty/locked/error 和横屏。

**退出门：** 六面可达且关闭后焦点回原触发控件；命令只提交一次；`party` 有独立证据；战斗主界面无回归；战斗关键帧通过 K3 的状态与横屏部分。

## U8：局内推进页

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-08-U8-run-progression.md`，覆盖 `summary`、`shop`、`omen`、`map`，明确奖励比较、费用/条件、事件选择、境域可达性与安全继续路径。

**失败测试：** 先覆盖“本轮无变化”、无奖励、费用不足、无事件、无可达节点、领取/购买重复提交与返回恢复；任何页面无安全继续路径时失败。

**Demo：** 实际 Cocos 固定种子从战斗结算经商店/机缘进入地图，展示 locked、empty、网络错误重试与横屏双栏，随后继续下一境域。

**退出门：** 四页主任务闭环；奖励和路径结果与迁移前一致；重复提交不改变结果；五态与双向证据齐全；局内完整流程不依赖旧呈现。

## U9：结局与孵化

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-09-U9-outcomes-hatch.md`，覆盖 `defeat`、`victory`、`hatch`，定义结算一次性提交、缺失明细、动画跳过、回厅和中断恢复。

**失败测试：** 先覆盖胜负结果只记一次、重复点按、结算中断恢复、揭晓数据缺失、资源错误、跳过动画后内容一致与回厅失败恢复；旧实现的非幂等路径必须暴露为 RED。

**Demo：** 实际 Cocos 分别演示失败、胜利、孵化及动画跳过；在提交前后模拟中断并恢复；展示五态、减少动效和横屏。

**退出门：** 三页结果幂等且能回厅；空明细仍可理解；孵化内容不因跳过改变；所有 25 产品面已迁移或有明确逐页回退记录。

## U10：全局横屏、可访问性、性能与包体

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-10-U10-quality-gates.md`，以 25×状态×方向矩阵安排修复；包含自动对比度/热区审计、焦点、200% 文本、减少动效、内存/Draw Call/帧率、两平台最终包分析。

**失败测试：** 先让矩阵对任一缺页/缺态/缺方向失败；让对比度、热区、焦点、闪烁、预算超限和主包 `>4 MiB` 分别以可复现夹具失败；不得只测成功样本。

**Demo：** 实际 Cocos 随机抽取页面现场切换五态、方向、文本 200% 与减少动效；在指定设备跑 15 分钟战斗/大厅循环；打开两平台最终构建报告。

**退出门：** 三关键帧 K3 全过；25 面双向可用；可访问性条目无缺陷；所有性能预算达标；两平台主包各 `≤4 MiB`；无占位产物；旧呈现仅保留受控回退。

## U11：产品化总验收与旧呈现退役决策

**详细计划：** 开工前创建 `docs/superpowers/plans/2026-09-11-U11-release-acceptance.md`，逐项映射产品规格总门、真实截图清单、固定种子旅程、两平台构建、回退演练、clean-room 复核和旧 Boot 去留决策。

**失败测试：** 先对缺截图元数据、替身截图、不可达页面、状态矩阵缺口、包体/性能回退、旧新双挂载和禁用词命中建立发布阻断测试；任何一项缺失均使发布审计失败。

**Demo：** 使用两平台实际最终 Cocos 构建完成“标题→模式→初始→战斗→战后→地图→结局→回厅”的固定种子旅程；抽查大厅资料页、五态、横屏、减少动效，并现场演练全局回退。

**退出门：** 产品规格第 9.3 节七项全部有新鲜证据；25 个产品面截图/状态/方向矩阵完整；两平台发布审计通过；独立复核无 Critical/Important 问题；若回退窗口结束，另开明确删除计划，U11 不顺手删除未验证边界。

## 完成定义

只有 U0–U11 按序通过各自退出门，才可称“UI 产品化完成”。阶段 Demo、静态截图或单个平台通过均不能替代退出门。任何阶段失败都停留在该阶段，记录证据并修复，不拆分编号、不跳阶段、不把失败项顺延为默认技术债。

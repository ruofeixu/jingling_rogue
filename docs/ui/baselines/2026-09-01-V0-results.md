## 2. V0-4 根因：不是数据问题，是转译缺陷

真实调用栈（web 构建 + 无头 Chrome + `Debugger.setPauseOnExceptions=all`）：

```text
getSpirit           index.js:8860
(anon)              index.js:11484   <- codex.filter 的回调
recordCatch         index.js:11483
ClassicSlice        index.js:13129
startRun            index.js:15907
beginUiRun          index.js:16189
Boot.startRun       index.js:378
```

源码写的是 `const codex = [...new Set([...base.codex, run.starterId, ...run.caughtIds])];`，
Creator 的脚本构建把它降级成：

```js
var codex = [].concat(/* @__PURE__ */new Set([].concat(base.codex, [run.starterId], run.caughtIds)));
```

`[].concat(aSet)` **不会迭代 Set**，而是把 Set 当成一个元素塞进数组。后果有两处：

1. `codex === [Set]` → `codex.filter((id) => getSpirit(id).starter)` 调到 `getSpirit(Set)` →
   抛 `unknown spirit: [object Set]`。`Boot.startRun` 的 `catch` 把它写进日志，开局静默失败。
2. `PORTRAIT_IDS = new Set([].concat(FIRST, SECOND, THIRD))` 变成装着 3 个 Set 的 Set，
   `PORTRAIT_IDS.has(id)` 恒为 `false` → `hasPortrait()` 永远假 → **构建后立绘从来没显示过**。
   这一条在 U0 基线里没被发现，因为它不报错，只是静默不画。

修复：`packages/core/src` 中 7 处对 Set 的数组展开改为 `Array.from(...)`
（`assets/manifest.ts`、`meta/miasma.ts`、`run/run-session.ts` ×5），并新增守卫测试
`packages/core/src/build-safety.test.ts` 扫描源码禁止该写法（先 RED 7 条，后 GREEN）。

## 3. V0-3 做法与实测

1. **引擎裁剪**：`settings/v2/packages/engine.json` 的 `includeModules` =
   `base / gfx-webgl / gfx-webgl2 / 3d / primitive / 2d / ui / tween / animation / intersection-2d / audio`。
   `cocos-js` 从 4,144,561 B 降到约 1.75 MB（bullet.wasm、spine.wasm 不再打包）。
   过程中裁过头两次并已修正：缺 `3d` 报 `Can not find class 'cc.DirectionalLight'`，
   缺 `primitive` 报 `Skybox.activate` 读 `'box'` 失败。
2. **立绘独立 Bundle**：`assets/resources/remote` → `assets/portraits`（`assets/portraits.meta`
   带 `isBundle` / `bundleName: portraits`）。`portraitTexturePath` 改为分包内相对路径
   `spirits/<id>/texture`，新增导出 `PORTRAIT_BUNDLE`，`assets/scripts/ui/portrait.ts` 改用
   `assetManager.loadBundle('portraits')` + `bundle.load`。
3. **构建后分包**：Creator 3.8.2 实测**忽略** `.meta` 里的 `compressionType`
   （`subpackage`、`zip` 都试过；也试过去掉 `bundleConfigID`、关构建缓存、用
   `configPath` 传 `bundleConfigs`，均未产出 `subpackages/`）。因此新增
   `tools/pack_subpackages.py`，按引擎适配层的真实契约做四件事：
   - `assets/<name>` → `subpackages/<name>`
   - `src/settings.json` 的 `assets.subpackages` 追加 `<name>`
   - `game.json` 的 `subpackages` 追加 `{name, root}`
   - 在分包根写 `game.js` 入口（抖音会直接报 `'subpackages/portraits/' should have game.js`）

   引擎侧依据（构建产物 `engine-adapter.js`）：
   ```js
   cc.settings.querySettings("assets", "subpackages")
       .forEach((name) => (_[name] = "subpackages/" + name));
   ```

实测产物（`.u0-build3/`，`pnpm pack:subpackages` 之后）：

| 平台 | 主包 | 分包 | assets | cocos-js | 文件数 | 4 MiB 门 |

| 微信小游戏 | 3,309,255 B | 15,281,447 B | 1,362,634 B | 1,745,300 B | 152 | PASS |
| 抖音小游戏 | 3,421,458 B | 15,281,447 B | 1,521,270 B | 1,750,129 B | 151 | PASS |

`pnpm check:cocos-build --wechat ... --bytedance ...` 退出码 0。聚合 SHA-256：

- 微信 `3ec59984c78dc99a2d2da6beb1fabaa8fa2d6b1e42ca50258fa2ec65ae8502df`
- 抖音 `52f3fe2747ec47cc9cb99579ac48b1aeba2c217f691907005bef90749ee916f9`

### 5.3 自动化通道实测

| 能力 | 结果 |
|---|---|
| `get_simulator_console` | 可用 |
| `automation_game_action --action tap` | **可用**，按画布坐标点按有效，是驱动小游戏的正确工具 |
| `automation_evaluate` | 可用，但运行在小游戏 **service** 上下文：`typeof wx === "object"`，`cc` / `GameGlobal.cc` 均 `undefined`，因此拿不到 Draw Call / FPS |
| `simulator_screenshot` | 始终 `waitForAutomatorReady timeout`；已试过 `open_project_window`、`cli auto --trust-project`、`cli auto --auto-port 9420`（9420 确认监听）、只留单窗口，均未解除 |
| `screencapture -x -o -l <windowId>` | 可用（`-o` 去窗口阴影，像素与窗口点严格 2:1）。**必须先 `open -a` 把窗口前置**，否则后台窗口不重绘，会连续截到同一帧 |
| 合成点击（CGEvent） | 权限正常（`AXIsProcessTrusted: true`，`CGWarpMouseCursorPosition` 生效）。之前点不中是坐标算错：带阴影的 `screencapture -l` 图比窗口大 136 px，不能直接按 2:1 换算 |

画布坐标由核心布局推算，避免目测：`screenLayout(750,1334)` 的设计坐标 → 微信 `390×844`
（`EXACT_FIT`）canvas 坐标为 `x=(375+dx)*390/750`、`y=(667-dy)*844/1334`。
标题/模式页首个按钮 `(125, 290)`，初始选择首张卡 `(72, 466)`。

抖音没有等价的画布点按接口，改用 CGEvent 按屏幕坐标点按：先 `open -a` 前置窗口，再用
`screencapture -x -o -l <windowId>` 取无阴影图（严格 2:1），用像素分析定位橙色主按钮包围盒
（`r>225 && 130<g<185 && 60<b<130`），中心换算 `screen = 窗口原点 + 像素/2`。实测坐标：
模式页入口 `(277.5, 430)`、短征 `(278, 436)`、初始选择首张卡 `(236, 528)`。
每次点按前都要重新前置窗口，否则事件不被接收。


## 6. 性能采样

### 6.1 平台侧（真实开发者工具）

| 指标 | 微信 | 抖音 |
|---|---|---|
| `LoadScene db://assets/boot.scene` | 84.4 ms（单次） | 51.09 ms（单次） |
| 首帧后 long-animation-frame | 82.4 ms（start 290.9 ms） | 未采 |
| 基础库 / SDK | 3.16.2 | 4.19.0 |
| 机型 / 分辨率 / DPR | iPhone 12/13 (Pro)，390×844，3 | iPhone 15 Pro，393×852，3 |
| 内存信息 | `memorySize: 2048`，`benchmarkLevel: -1` | 未采 |

微信刷新到 `jingling boot` 可见的墙钟耗时三次：`1087 / 13787 / 981 ms`。这个数**不能当冷启动指标**：
它包含开发者工具重新编译与 200 ms 轮询粒度，13787 ms 那次明显是工具重编译。`LoadScene` 的
`console.timeEnd` 不进 `get_simulator_console` 的缓冲，所以平台侧多次采样目前只能靠人工读控制台。

### 6.2 web 构建侧（同一份代码，**不能替代平台数据**）

`build-configs/web-mobile.json` 构建 + 无头 Chrome（SwiftShader 软件 WebGL）。

| 指标 | 3 次重载 | 中位数 |
|---|---|---|
| Init Infrastructure | 24.29 / 37.22 / 31.93 ms | 31.93 ms |
| Init SubSystem | 25.22 / 21.89 / 21.44 ms | 21.89 ms |
| Init Project | 22.80 / 21.75 / 22.21 ms | 22.21 ms |

| 页面 | Draw Call 峰值 | 场景节点总数 |
|---|---:|---:|
| 标题页 | 35 | 50 |
| 战斗页（第 1 波） | 41 | 55 |

Draw Call 与节点数由引擎自己统计（`cc.director.root.device.numDrawCalls`、递归遍历场景），
与 GPU 快慢无关，可以直接用作对照基线。

**FPS 不给结论**：同环境测得 27.5 fps（83 帧 / 3.02 s），但这是软件光栅化的无头 Chrome，
既非平台也非真机，拿它谈帧率没有意义。真实 FPS 需要真机或在产品里挂 Cocos `profiler`。

## 8. 非证据项

- `.u0-build3/` 下的 `diag-web.mjs`、`eval-web.mjs`、`trace-web.mjs`、`perf-web.mjs` 是一次性诊断脚本，不是产品代码。
- web-mobile 构建（`build-configs/web-mobile.json`）只用于抓真实调用栈与引擎侧计数，不是发布目标，其 FPS 无参考价值。
- 无头 Chrome 需要 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`，否则没有 WebGL。
